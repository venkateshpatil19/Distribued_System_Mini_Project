# Lab 6: Design and deploy a small distributed application (DeployGuard)

**Aim:** design and deploy a small distributed application that demonstrates scalability and inter-service communication.

The application is DeployGuard itself (the rest of this repository).

## Services and how they communicate
| From | To | Protocol | Purpose |
|---|---|---|---|
| Agent | Leader controller | gRPC (HTTP/2) | Register, heartbeat (beacon), pull config, get time (Cristian) |
| Leader controller | Agent | gRPC heartbeat reply | Commands in order: faults, traffic settings, snapshot markers |
| Agent | Leader controller | gRPC `Report` | Acks, metrics, snapshot markers (resent until accepted) |
| Controller | Controller | gRPC | Bully election, leader heartbeats, state replication, forwarded requests |
| Controller | Its own disk | JSON file | Durable copy of the replicated state |
| Dashboard | Controller | HTTP + Server-Sent Events | UI and live updates |

## Deploy (multi-process)
Follow the root `README.md`: build the jar and the dashboard, then run `start.bat` (Windows) or `scripts/run-local.sh`. This starts 3 controllers and 3 agents as independent OS processes.

## Demonstrate scalability
Scale the agents while the system runs; new replicas register, pull the current configuration and start serving without any change to the controllers:
```bash
docker compose up -d --scale agent=10     # or: scale.bat 10, which also measures it
```
Measured on one machine: throughput grows linearly (122 requests/s with 3 agents, 796 with 20) while a configuration change still reaches every agent in about 1.2 s. Full table and explanation: `docs/SCALABILITY.md`.

## Demonstrate failure recovery
Run the real-world demo: `demo.bat` (which runs `scripts/demo.ps1`). It covers a healthy staged rollout, a broken release that rolls back automatically, leader failover, and agent partition and recovery. Expected results are in `docs/DEMO.md`.

## Docker
`docker-compose.yml` runs the same system in containers: 3 controllers, a scalable agent service (3 replicas by default) and the dashboard (`backend/Dockerfile`, `frontend/Dockerfile`, both multi-stage builds from source). Start with `docker-start.bat` or `docker compose up -d --build`. Containers talk over the Compose network by service name, controller state lives in a named volume, and `restart: unless-stopped` brings back a crashed container. Kubernetes manifests are not part of this version.

Traffic and faults are generated by the agents' simulator and are labelled `simulated` in the event log and the UI.
